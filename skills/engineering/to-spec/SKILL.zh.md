此技能會擷取目前的對話脈絡與程式碼庫理解，並產出規格說明。請勿訪談使用者；只需綜合整理您已知的資訊。

問題追蹤系統與分級標籤詞彙應已提供給您。若未提供，請告知使用者執行 `/setup-matt-pocock-skills`。

<a id="process"></a>

## 流程

1. 若尚未探索儲存庫，請先探索以瞭解程式碼庫的目前狀態。在規格說明中全程使用專案的領域詞彙表，並尊重您所涉及領域中的任何 ADR。

2. 勾勒出您將用於測試此功能的接縫點。應優先使用現有的接縫點，而非建立新的。使用可能的最高層級接縫點。若需要新的接縫點，請在您可以達到的最高層級提出建議。程式碼庫中的接縫點越少越好，理想數量為一個。

與使用者確認這些接縫點是否符合其預期。

3. 使用下方的範本撰寫規格說明，然後釋出至專案問題追蹤系統。套用 `ready-for-agent` 分級標籤，無需進行額外的分級。

## 使用者故事

一份長篇的編號使用者故事清單。每個使用者故事應採用以下格式：

1. 身為 <actor>，我希望擁有 <feature>，以便 <benefit>

<user-story-example>
1. 身為行動銀行客戶，我希望看到帳戶餘額，以便我能就消費做出更明智的決策
</user-story-example>

這份使用者故事清單應極為詳盡，涵蓋該功能的所有面向。

<a id="implementation-decisions"></a>

## 實作決策

已做出的實作決策清單。可包含：

- 將建立或修改的模組
- 將修改的這些模組的介面
- 開發人員提供的技術澄清
- 架構決策
- 資料庫結構變更
- API 合約
- 特定的互動

請勿包含特定的檔案路徑或程式碼片段。它們可能很快就會過時。

例外情況：若原型產生了一段能比文字更精確地編碼決策的片段（狀態機、reducer、資料庫結構、型別形狀），請將其內嵌於相關的決策中，並簡短註明其來自原型。僅保留富含決策資訊的部分，而非可運作的示範，只要重要的部分即可。

- 將被測試的模組
