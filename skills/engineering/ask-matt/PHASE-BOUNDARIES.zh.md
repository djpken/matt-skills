# 階段邊界

**階段（phase）**是 session 裡的一塊工作——grilling、implementation、QA。這個定義故意留得模糊：一個階段結束於你心想*「好，這塊做完了」*的那一刻。

**階段邊界（phase boundary）**是兩個階段之間的空隙，也是這個決策唯一該出現的地方。階段中途沒有這個決策可做——只有繼續，或把剩下的工作拆給 subagents。在階段中途 compact 會讓 agent 迷失方向。

## 五個選項

| 選項         | 它做什麼                                                    |
| ------------ | --------------------------------------------------------- |
| **Continue** | 留在 session 裡。完全不切換 context。                       |
| **`/clear`** | 清空 context 視窗，從零開始。                               |
| **`/handoff`** | 寫一份可攜的 Markdown 檔案，用它在任何地方起一個新 session。 |
| **Subagent** | 把任務送進它自己的 context 視窗，拿回一份報告。              |
| **`/compact`** | 壓縮這段 context，用摘要播種一個新 session。                 |

## 這棵決策樹

在邊界上由上往下走。第一個**是**就贏。

**1. 你能在這個 session 裡繼續嗎？** 兩件事會讓答案是「是」：下一個階段需要這個階段作為 **primary source**，或是你還有足夠的 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（約 150k tokens）留給下一個階段用。Grilling → implementation 是標準的「是」：implementation 想要一字不漏的推理過程，而不是它的摘要。Continue 不花代價也不損失任何東西，所以先排除它，其他都不用想了。

**2. 這段 context 和接下來要做的事無關嗎？** 這個 session 裡的一切——探索、決策、死路——都是可拋棄的嗎？如果是，用 **`/clear`**。這是盤面上最便宜的一步：不花時間，還能整個拿回視窗。`/clear` 也不是終點——舊 session 仍然可以恢復。

猜錯的代價是單向的。清空一段*有關*的 context，你就失去了建置背後的**為什麼**，之後怎麼讀 diff 都補不回來。

**3. 你需要交接嗎？** `/handoff` 用途很窄。只有在你以下情況才需要它：

- 換到**新的 harness**（Claude → Codex），
- 移到**新的目錄**或 repo，
- 把工作交給**同事**，
- 或是在**階段中途**分出一個附帶任務，又不想打斷手上正在做的事。

那份清單就是全部條件。`/handoff` 買到的是**可攜性（portability）**——一個能移動的檔案。如果沒有東西要移動，你就不需要它。

**4. 這個任務能在你不在場（AFK）時完成嗎？** 範圍夠緊，緊到可以在你離開鍵盤、不用引導的情況下跑完嗎？那就送去 **subagent**，這個 session 保持不動。自動化 review 是標準案例：agent 讀 diff 並回報，過程中不需要你。

**5. 其他情況，用 `/compact`。** 相關的 context、同一個 harness、同一個目錄，而且你需要留在迴路裡——這棵樹最後常常落在這裡。附上一個指示（`/compact we're going to QA this area`），讓摘要保留下一個階段需要的東西。

`/compact` 是**預設選項，不是第一個該伸手拿的**。它排在最底層，因為前面四個問題都比它更便宜或更精準。從這裡開始的失敗模式，是一個對摘要抹平掉的某個決策自信滿滿地搞錯的全新 session。

## Primary source 與 secondary source

除了 **Continue**，每一步都把一個 **primary source** 變成 **secondary source**——把 session 實際發生的過程，換成它的摘要。這筆交易永遠是同樣的形狀：

| Source                              | 資訊量 | 雜訊 | 迴旋空間 |
| ------------------------------------ | ---- | ---- | -------- |
| Primary（Continue）                  | 完整  | 多   | 少       |
| Secondary（`/compact`、`/handoff`）  | 有損  | 少   | 多       |

這就是為什麼問題 1 要先問。只有當留在原地的代價高於它省下的東西時，你才需要付這個有損的代價。

## 這些都是判斷題

這些問題不是客觀的——每一題都帶著品味，同一個邊界在兩天可能走出兩種答案。價值在於**依序**問這些問題，而且是在邊界上問，而不是在工作中途問。
