給任何 agent 會消費的文件用的參考——一個 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份被指針指向的文件。封裝方式不同，但寫法不變：同一組槓桿讓每一種都變得可預測——是 agent 每次執行都走同一套*流程*，而不是每次產出同一份輸出。

當你要寫的文件是一個 skill 時，讀 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、呼叫方式的選擇，以及路由器 skill。

## Context 指針

**Context 指針（context pointer）**是留在 agent context 裡的一個參照，指名某段 context 之外的材料，並編碼觸及它的條件。Skill 的 description 是一個；`AGENTS.md` 裡指名某份文件的一行，是同一種東西。決定 agent 何時、以及多可靠地觸及材料的，是指針的*措辭*，而不是它指向的目標——一個措辭薄弱的指針背後藏著一個必要的目標，就是一個變異 bug：先把措辭磨利，只有在磨利失敗時才把材料內嵌進來。

一個指針做兩件事——說明材料是什麼，並列出應該觸發去觸及它的**分支（branches）**（分支是文件處理的一個明確案例，所以不同的執行會走過它不同的路徑）。一個常駐載入的指針，每個詞都要在每個回合付出代價，所以它比正文更需要嚴格修剪：

- **把主導詞前置**——指針正是它做呼叫工作的地方。
- **每個分支一個觸發。** 把同一個分支換個說法講兩遍，其實是同一個分支寫了兩次；折疊它們，只留下真正不同的分支。
- **剪掉正文已經帶有的身份描述。**

## 兩種負載

你新增的每份文件和每個指針，都花掉兩種預算之一：

- **Context 負載（context load）**——常駐載入材料對 agent 視窗的成本：一行 `AGENTS.md`、一個 skill description，任何每個回合都坐在 context 裡的東西，不管它有沒有被觸發，都要付 token 和注意力。
- **認知負載（cognitive load）**——這個成本落在人類身上：有哪些文件存在、什麼時候該去查哪一份。人類是那個索引。這不是要盡量壓低的成本——它是人類自主判斷的代價；把它花在人類的判斷真正重要的地方，在不重要的地方移除它。

只透過指針才能觸及的材料，用指針自身那一行的代價，換來逃開 context 負載；完全沒有指針的材料，則整個成本都落在認知負載上。

## 資訊層次

一份文件由兩種內容類型構成——**步驟（steps）**（agent 執行的有序動作）和**參考（reference）**（按需查閱的定義、規則、事實）——可以自由混合：全是步驟（一份食譜）、全是參考（一次 review 的規則、這個 skill 本身），或兩者兼有。核心決策是每一段材料坐在**資訊層次（information hierarchy）**的哪一階——一把按 agent 多迫切需要這段材料排名的梯子：

1. **檔案內步驟** — 主要層：agent 依序做什麼。
2. **檔案內參考** — 按需查閱。常常是合理的扁平同等集（一次 review 的每條規則都在同一階）——這是恰當的安排，不是問題。
3. **披露式參考（disclosed reference）** — 推出到獨立檔案，透過 context 指針觸及，只在指針觸發時載入。從同一資料夾裡的兄弟檔案，一路到存在於任何地方、任何文件都能指向的完全外部參考，都算在內。

推得太少，頂層就膨脹；推得太多，你就藏住了 agent 實際需要的材料。這個張力就是整個決策。

**漸進披露（Progressive disclosure）**是沿著這把梯子往下移動的動作——移出主檔案、藏到指針後面——讓頂層保持可讀。它主要不是 token 最佳化：它是保護這個層次結構的手段。分支是最乾淨的披露測試：把每個分支都需要的東西內嵌，把只有部分分支才會觸及的東西推到指針後面。當一份文件有步驟時，本該被披露出去的檔案內參考會埋沒它們，把「有沒有留意到它」變成一場硬幣翻轉——這是一個影響變異的槓桿，不只是可讀性的槓桿。

**共同定位（Co-location）**是檔案內的搭檔：層次決定一段材料坐得*多深*，共同定位則決定它一旦落腳，*什麼坐在它旁邊*。把一個概念的定義、規則和注意事項放在同一個標題下，而不是分散各處，讓讀到其中一部分，就順便帶出它的鄰居。判準：這份文件讀起來該像是專門為 agent 寫的文件——分好組的材料讀起來就是這樣；散落各處的不是。（這和重複不同：重複是同一個含義出現在兩個地方；散落是把一個含義打散在許多地方。）

**蔓延（Sprawl）**是這裡的失敗模式：一份文件單純太長，就算每一行都是活的、獨一無二的。注意力隨著篇幅稀釋，每多一行就多一件要保持相關的事。解方就是這把梯子：把參考披露到指針後面，並按分支或依序拆分，讓每條路徑只帶著它需要的東西。

## 步驟與完成標準

每個步驟都以一個**完成標準（completion criterion）**收尾——告訴 agent 工作已完成的條件。兩個屬性讓它成為一個槓桿：

- **清晰度** — agent 能分辨完成和未完成嗎？模糊的界線（「理解已經到位」）會招來**過早完成（premature completion）**：在真正做完之前就結束這個步驟，注意力滑向*已完成*這件事本身。看得見的、還在前面等著的步驟——**完成後步驟（post-completion steps）**——是那股拉力；標準的清晰度是抵抗它的阻力。按順序防禦：**先磨利界線**（局部又便宜）；只有當它不可化簡地模糊，*而且*你真的觀察到了倉促，才把後面的步驟藏起來，靠拆分序列——而藏起來只在跨越真正的 context 邊界時才有效（一次交接或一次 subagent 派工；一次內嵌呼叫並不會清空 context，後面的步驟還在那裡）。
- **要求量** — 它要求多少。「每個修改過的模型都要說明」逼出徹底的工作，而「產出一份變更清單」不會。要求量驅動**腿力（legwork）**——agent 在工作內部做的深挖，潛藏在措辭裡，不是自成一步——而且它不只綁在步驟上：「每條規則都套用了」綁定一整塊扁平參考，就跟「每個步驟都做完了」綁定一段序列一樣，這正是為什麼一份全是參考的文件依然能帶有詳盡的標準。

最強的標準同時是可檢查的，也是詳盡的。

## 何時拆分

把一份文件拆成兩份，花掉的是兩種負載之一，所以只有在這一刀值得時才拆：

- **依序拆分** — 在後面的步驟誘使 agent 倉促做完前面那一步時，把一段步驟序列切開。讓它們留在視野之外，能逼出對當前任務更多的腿力。反過來也要小心：把幾段序列合併，會把每個步驟後面的步驟暴露出來，招來過早完成。
- **依呼叫方式拆分** — 這是 skill 特有的：見 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 主導詞

**主導詞（leading word）**是一個緊湊的概念，已經活在模型的預訓練裡，agent 執行這份文件時會用它來思考（*lesson*、*fog of war*、*tracer bullets*）。以 token 的形式重複出現，而不是以句子的形式，它會累積出一個分散的定義，並透過招募模型已經持有的先驗，用最少的 token 錨定一整片行為區域。用自己造的詞也行，只要定義得夠清楚，但一個自創詞招不到任何先驗——你得用定義的 token 去付出一個已預訓練詞白白給你的東西；先試著找一個已經存在的詞。

它錨定兩次。在正文裡，它錨定*執行*：每次這個詞出現，agent 都會伸手去做同一件事，在扁平參考裡，它把注意力聚焦到一類該找的東西上。在指針裡，它錨定*呼叫*：當同一個詞同時活在你的 prompt、你的文件、你的程式碼裡，agent 就能把那個共享的語言連到這份材料，更可靠地觸及它。

去獵找可以用主導詞重構的機會。在三個地方各自拼出一遍的三元組，一個指針花一整句去比劃一個想法——每一個都是一段在乞求折疊成單一 token 的文字：

- 「快速、確定性、低開銷」→ *tight*（一個*緊密*的迴圈）。
- 「一個你信得過的迴圈」→ *red*——把一個模糊的門檻變成一個二元、可觀察的狀態（迴圈在那個 bug 上變*紅*，或者不變）。

你賺兩次：更少的 token，*而且*給 agent 一個更清晰的鉤子掛上它的思考。假設每份文件都帶著主導詞能退休掉的重述——去把它們找出來。

**否定（Negation）**是這個槓桿旁邊的失敗模式：用禁止來引導，會把被禁止的行為拖進 context，讓它*更*容易被想起，而不是更少。*別想大象*，於是滿腦子只剩大象；否定是個弱修飾詞，會被那個被強力激活的概念蓋過去，所以禁令讀起來有一半像是在指示去做那件事。要提示**正面**的行為——直接陳述目標行為（「寫一行的注釋」），讓被禁止的那個從未被說出口。只有在真的無法正面表述的硬性防線上才保留禁止句，就算如此，也要搭配正面目標，讓注意力落在該做什麼上。

## 修剪

- 把每個含義保持在**單一真相來源（single source of truth）**：一個權威的地方，改變行為就是一個地方的編輯。**重複（duplication）**——同一個含義出現在不只一個地方——會增加維護成本和 token，並在層次上把一個含義的重要性膨脹到超過它實際的等級。（這是主導詞的意外反面：主導詞是刻意重複一個 token，絕不重複含義。）
- **環境（environment）**本身也是一個真相來源——`package.json` 的 scripts、設定檔、目錄結構、`--help` 的輸出——一份重述它的文件就是一個**快取（cache）**：一份查詢結果的副本，只有在查詢本身很貴時，才值得付這個負載。快取 agent 用查的找不到的東西：沒寫下來的慣例、選擇背後的原因、沒有任何設定會坦白的坑。把一查就有、一個指令就有的東西留給環境，那裡永遠不會過時。
- 檢查每一行的**相關性（relevance）**：它還跟這份文件在做的事有關嗎？一行會因為從未真正牽動任務（純粹的說明文字，或者一個本該被披露出去的分支）而失去相關性，也會因為它描述的行為或世界改變而過時。文件愈短，愈容易保持相關。沒有修剪紀律，預設的命運就是**沉積（sediment）**：因為新增感覺安全、移除感覺有風險，一層層過時的內容沉澱下來，直到你得一路挖穿它們才能找到還活著的部分。
- 逐句而不是逐行獵找**無操作（no-ops）**：模型預設就已經會做的一個指示，付出負載卻什麼都沒改變。判準——它跟預設相比，改變行為了嗎？——是相對於模型的，不是相對於讀者的：兩個人對同一句是不是無操作有分歧，那是他們對「預設」的認知不同，要靠跑一次這份文件來解決，不是靠爭論。一句話沒通過測試，就整句刪掉，不要只是刪幾個詞。這個測試也會拿主導詞開刀：一個弱到贏不過預設的詞（agent 本來就已經算徹底時還說*要徹底*）是無操作，修法是換一個更強的詞（*無情*），而不是換一種技巧。
