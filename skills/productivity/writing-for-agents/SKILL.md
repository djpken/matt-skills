撰寫任何 agent 所消費之檔案的參考：一個 skill、一個 `AGENTS.md` / `CLAUDE.md`，或透過指標到達的檔案。包裝方式不同，撰寫方式相同：相同的槓桿使每一項都可預測，因為 agent 每次執行都採取相同的 _流程_，而非產生相同的輸出。

當您撰寫的檔案是 skill 時，請閱讀 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 以瞭解 frontmatter、呼叫選擇以及 router skills。

<a id="context-pointers"></a>

## 上下文指標

**上下文指標**是保留在 agent 上下文中的一個參考，它命名了某些上下文之外的材料，並編碼了到達該材料的條件。skill 的描述是一個例子；`AGENTS.md` 中命名某個檔案的一行也是同一個物件。指標的 _措辭_，而非其目標，決定了 agent 何時到達該材料，以及到達的可靠性。一個必須具備的目標背後若有一個措辭薄弱的指標，就是一個變異錯誤：先 sharpen 措辭，只有當 sharpen 失敗時才將材料內聯。

指標執行兩項工作：說明材料是什麼，並列出應觸發到達該材料的 **分支**（分支是檔案處理的不同案例，因此不同的執行會透過它採取不同的路徑）。每個始終載入的指標中的每個字都在每一輪中產生成本，因此它比正文更需要更嚴格的修剪：

- **將關鍵詞前置**：指標是執行觸發工作的地方。
- **每個分支一個觸發器。** 重新命名單一分支的同義詞是同一個分支寫了兩次；合併它們，只保留真正不同的分支。
- **刪除正文已經包含的身份資訊。**

<a id="the-two-loads"></a>

## 兩種負載

您新增的每個檔案和指標都會花費兩種預算之一：

- **上下文負載**是始終載入材料對 agent 視窗的成本：一行 `AGENTS.md`、一個 skill 描述、任何在每一輪都位於上下文中的內容，無論是否觸發，都會消耗 token 和注意力。
- **認知負載**是對人類造成的成本：哪些檔案存在，以及何時使用每一個。人類是索引。這不是要最小化的成本：這是人類自主性的代價；在人類判斷重要的地方花費它，在不重要的地方移除它。

僅透過指標到達的材料，以指標自身的行為代價逃脫了上下文負載；完全沒有指標的材料則完全依賴認知負載。

<a id="information-hierarchy"></a>

## 資訊層級

檔案由兩種內容型別構成：**步驟**（agent 執行的有序動作）和**參考**（按需查閱的定義、規則、事實）。兩者可以自由混合：全部是步驟（一個食譜）、全部是參考（審查的規則、這個 skill），或兩者皆有。核心決策是每個部分在**資訊層級**上的位置，這是一個根據 agent 需要材料的即時程度進行排序的階梯：

1. **檔案內步驟**是主要層級：agent 按順序執行的內容。
2. **檔案內參考**是按需查閱的。通常是一個合法的扁平同級集合（審查的每一條規則都在同一級），這是一個合理的安排，而非壞味道。
3. **披露參考**被推送到單獨的檔案中，透過上下文指標到達，僅在指標觸發時載入。範圍從同一資料夾中的同級檔案，到完全外部的參考（可存在於任何地方，任何檔案都可以指向它）。

向下推送太少，頂部會膨脹；推送太多，會隱藏 agent 實際需要的材料。這種張力就是整個決策的核心。

**漸進式披露**是沿階梯向下的動作（移出主檔案並置於指標之後），以保持頂部清晰可讀。這主要不是 token 最佳化：這是保護層級的方式。分支是最乾淨的披露測試：內聯每個分支所需的內容，並將只有部分分支到達的內容推至指標之後。當檔案包含步驟時，應該披露的檔案內參考會掩蓋這些步驟，並使關注它們變成拋硬幣：這是一個變異槓桿，而不僅是清晰度的問題。

**共置**是檔案內的伴隨概念：當階梯決定一個部分 _向下多少_ 時，共置決定 _在那裡什麼與它並列_。將一個概念的定義、規則和注意事項放在同一標題下，而不是分散在各處，以便閱讀其中一部分時能帶出其相鄰內容。測試標準：檔案應該讀起來像是為 agent 撰寫的檔案。分組的材料讀起來像這樣；分散的材料則不然。（與重複不同：重複是在兩個地方重複同一個意義；分散是將一個意義碎片化到多個地方。）

**蔓延**是此處的失敗模式：檔案單純太長，即使每一行都是活躍且獨特的。注意力在過多的內容中變薄，每一行額外的內容都是需要保持相關性的一行。解藥是階梯：透過指標披露參考，並按分支或順序拆分，使每條路徑只攜帶其所需的內容。

<a id="steps-and-completion-criteria"></a>

## 步驟與完成標準

每個步驟都以**完成標準**結束，這是告訴 agent 工作已完成的條件。兩個特性使其成為一個槓桿：

- **清晰度**：agent 能否分辨完成與未完成？模糊的邊界（「達到理解」）會誘發**過早完成**：在真正完成之前結束步驟，注意力滑向 _已完成_ 的狀態。前方可見的步驟（**完成後步驟**）提供拉力；標準的清晰度提供阻力。按順序防禦：**先 sharpen 邊界**（區域性且成本低）；只有當它不可約減地模糊 _且_ 您觀察到匆忙時，才透過拆分序列來隱藏後續步驟。隱藏只在真正的上下文邊界（交接或 subagent 排程）才有效；內聯呼叫會將後續步驟留在上下文中，什麼也清除不了。
- **要求**：它要求多少。「每個修改過的模型都已處理」在「產生變更清單」無法做到的地方強制徹底的工作。要求驅動**跑腿工作**（agent 在工作內進行的挖掘，潛在於措辭中，而非作為其自身的步驟寫出），並且它不受步驟限制：「每條規則都已應用」繫結一個扁平參考集合，就像「每個步驟都已完成」繫結一個序列一樣，這就是為什麼一個全參考檔案仍然攜帶一個完整性標準。

最強的標準既是可檢查的，又是窮盡的。

<a id="when-to-split"></a>

## 何時拆分

將一個檔案拆分為兩個會花費兩種負載之一，因此只有在切割值得時才拆分：

- **按順序**：拆分一連串步驟，其中完成後步驟誘使 agent 匆忙處理前面的步驟。將它們保持在視野之外會驅動當前任務更多的跑腿工作。警惕反向操作：合併序列會使每個步驟的後續步驟暴露給後續內容，誘發過早完成。
- **透過呼叫**，特定於 skill：請參閱 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

<a id="leading-words"></a>

## 領頭詞

**領頭詞**是一個緊湊的概念，它已經存在於模型的預訓練中，agent 在執行檔案時會以此進行思考（_lesson_、_fog of war_、_tracer bullets_）。作為一個 token 重複出現，而非作為一個句子，它累積了分散式定義，並以最少的 token 錨定整個行為區域，方法是呼叫模型已經持有的先驗知識。自創詞彙在定義清晰時也能運作，但自創詞無法呼叫先驗知識：你必須支付定義 token 的代價，而預訓練詞彙則是免費提供的；請優先使用現有的詞彙。

它兩次起到錨定作用。在正文中，_執行_：每次該詞出現時，agent 都會尋求相同的行為，而在扁平引用中，它將注意力集中在要查詢的事物類別上。在指標中，_呼叫_：當相同的詞存在於你的提示、檔案和程式碼庫中時，agent 會將這種共享語言與材料連結起來，並更可靠地找到它。

尋找使用領頭詞進行重構的機會。一個在三處明確寫出的三元組，一個指標花了一個句子來暗示一個想法。每一處都是渴望收縮為單一 token 的段落：

- "fast, deterministic, low-overhead" → _tight_（一個 _tight_ 迴圈）。
- "a loop you believe in" → _red_，將模糊的閘門轉化為二進位可觀察狀態（迴圈在 bug 上變 _red_，或者不變）。

你贏了兩次：更少的 token，以及一個更鋒利的掛鉤，讓 agent 可以掛上它的思考。假設每個檔案都承載著領頭詞可以取代的重述。去找到它們。

**否定**是這個槓桿旁邊的失敗模式：透過禁止來引導會將被禁止的行為拖入上下文，使其變得_更_可用，而不是更少。_不要想大象_，而大象就是全部；否定是一個弱修飾詞，被強烈啟用的概念所淹沒，因此禁令被半讀為執行該事情的指示。提示**正面**：說明目標行為（"寫一行註解"），這樣被禁止的行為就永遠不會被提及。禁止只有在無法以正面方式表述的硬性護欄中才值得佔據位置；即使如此，也要將其與正面目標配對，以便注意力落在要做的事情上。

<a id="pruning"></a>

## 修剪

- 將每個含義保留在**單一事實來源**中：一個權威位置，以便更改行為只需在一處編輯。**重複**（同一含義存在於多個位置）會增加維護和 token 成本，並使含義在階梯上的顯著性膨脹超過其真實排名。（這是領頭詞的意外反面，領頭詞故意重複 token，絕不重複含義。）
- **環境**也是一個事實來源（`package.json` 指令碼、設定檔、目錄結構、`--help` 輸出），而重述環境的檔案是一個**快取**：查詢的副本，僅在查詢昂貴時才值得承擔其負載。快取 agent 無法透過查詢找到的內容：未書寫的慣例、選擇背後的原因、沒有設定檔承認的陷阱。將單檔案、單命令的查詢留給環境，在那裡它們不會過時。
- 檢查每一行的**相關性**：它是否仍然與檔案的功能相關？一行文字會因為從未與任務相關（純粹的闡述，或應該披露的分支）或因為其描述的行為或世界變化而過時而失去相關性。較短的檔案更容易保持相關性。沒有修剪紀律，預設命運是**沉積物**：過時的層層堆積，因為增加感覺安全而移除感覺風險，直到你必須鑽透它們才能找到仍然活躍的內容。
- 逐句尋找**無效操作**：模型預設已經遵守的指示支付負載卻什麼也沒說。測試（它是否改變了預設行為？）是相對於模型的，而不是相對於讀者的：兩個人對無效操作的意見分歧是對預設的意見分歧，透過執行檔案來解決，而不是透過辯論。當一個句子失敗時，刪除整個句子，而不是從中刪減詞彙。測試也評估領頭詞：一個太弱以至於無法擊敗預設的詞（當 agent 已經相當徹底時使用 _be thorough_）是無效操作，修正方法是使用更強的詞（_relentless_），而不是不同的技術。
